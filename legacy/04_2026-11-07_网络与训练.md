## 3. 学习知识点

### 数据集统计与网络结构

`np.empty((sample_count, 4), dtype=np.float32)` 的外层圆括号用于函数调用，内层元组表示形状，不是只有写中括号才算数组。

`error_counts.items()` 遍历“算法名称、累计错误比特数”。`sample_count` 是数据符号数，QPSK 每符号 2 比特，所以基线 BER 的分母为 `2 * sample_count`。

网络中 `nn` 是 `torch.nn` 模块。批大小记为 `B` 时，数据形状依次为：

~~~text
[B, 4]
  → Linear(4, 128) → ReLU
[B, 128]
  → Linear(128, 128) → ReLU
[B, 128]
  → Linear(128, 4)
[B, 4]：四个类别的原始分数 logits
~~~

最后一层不加 Softmax，直接把 logits 交给 `CrossEntropyLoss`；该损失内部已包含相应的归一化计算。输出的四个分数分别对应 00、01、10、11，并不是四个比特。

`NeuralReceiver(nn.Module)` 继承框架功能，`super().__init__()` 初始化父类状态。把 `nn.Sequential(...)` 赋给 `self.network` 后，它既是对象属性，也是一个可调用的子模块。`self.network(features)` 调用这个对象处理输入；“属性”和“可以调用”并不矛盾。

`model(features)` 会经由 `nn.Module` 的调用机制执行 `forward()`。`train()`、`to()`、`parameters()` 和 `state_dict()` 等方法来自父类，不需要在 `model.py` 中逐个重写。

### 导入与项目入口

`from .config import Trainconfig` 中的点表示当前包，不是任意工作目录。因为使用包内相对导入，应在项目根目录用 `python -m week3.train` 运行，避免把 `train.py` 当孤立文件直接执行。

### 单轮训练和评估

`run_epoch(model, loader, device, optimizer=None)` 根据是否传入优化器决定是否更新参数：

| 步骤 | 训练 | 验证或测试 |
|---|---|---|
| 模型模式 | `model.train(True)` | `model.train(False)` |
| 自动求导 | 开启 | 通过 `torch.set_grad_enabled(False)` 关闭 |
| 前向传播、损失和 BER | 计算 | 计算 |
| 清空梯度、反向传播、更新参数 | 执行 | 不执行 |

训练时的关键顺序为：

~~~python
optimizer.zero_grad(set_to_none=True)
logits = model(features)
loss = criterion(logits, labels)
loss.backward()
optimizer.step()
~~~

这些语句分别负责清梯度、预测、计算损失、反向求梯度和更新权重。优化器对象在 `main()` 中通过 `torch.optim.AdamW(model.parameters(), ...)` 创建，再作为参数传入本函数。

`logits.detach().argmax(dim=1)` 沿每行的四个类别选最大分数对应的编号。`dim=0` 会跨样本比较，不适合这里的逐样本分类。`detach()` 使统计用张量脱离求导关系；本处 `argmax` 的索引输出本身也不可微。

类别编号还原成两个比特：`label // 2` 是第一个比特，`label % 2` 是第二个比特，再与预测结果逐比特比较。直接统计“类别是否相等”得到的是符号错误统计，不能不加区分地当作 BER。

## 4. 错误与修正

| 错误写法或现象 | 原因与正确方式 | 状态 |
|---|---|---|
| `self.network = ...` 与 `def __init__` 对齐，编辑器提示 `self`、`hidden_dim` 未定义 | 语句落到了方法外，应缩进到 `__init__` 内，与 `super().__init__()` 对齐。 | 当前源码已位于正确作用域，后续运行验证通过。 |
| `torch`、`numpy` 等出现无法解析导入的警告 | 需区分编辑器选择的解释器与终端执行的解释器，并检查包安装位置。 | 当日讨论排查方法；确切环境差异在 11 月 8 日核实。 |

另外有两项概念修正：

- `optimizer=None` 表示调用者没有提供优化器，由本函数选择评估路径；它不是禁用了全局优化器。
- `model.eval()` 或 `model.train(False)` 只切换模型模式，**不会自动关闭自动求导，也不会冻结所有参数**。本项目另外用 `set_grad_enabled` 控制梯度，且只在训练路径执行 `step()`。当前网络没有 Dropout、BatchNorm，切换模式本身不改变这几个层的数值计算。

## 5. 实验或问题分析

我开始把训练代码理解成一条明确的数据流：Dataset 保存样本 → DataLoader 分批提供样本 → 模型产生 logits → 损失衡量预测 → 优化器更新参数。验证复用前向和统计步骤，但不更新模型。

虽然输入和输出都是四维，它们含义不同：输入是一个子载波的四个物理特征，输出是四个类别的打分。网络没有把整个 64 点 OFDM 符号作为一次输入，也没有联合处理相邻子载波。

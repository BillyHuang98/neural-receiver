## 3. 学习知识点

### 当前神经接收机的定位

MLP 是多层感知机，即由全连接层和激活函数组成的前馈网络。本项目保留 FFT 和 LS 信道估计，用网络替代逐子载波均衡、硬判决这一部分，更准确地说是 **LS 辅助的神经符号检测器**。

本阶段先验证数据生成、训练、独立验证、保存和重新加载能否连起来。是否优于传统算法，要由后续实验判断。

### 配置与类

当前配置类名为 `Trainconfig`；原对话示例有时写作 `TrainConfig`。Python 区分大小写，使用时必须与当前定义一致。调用示例：

~~~python
from week3.config import Trainconfig

cfg = Trainconfig(mode="smoke")
print(cfg.hidden_dim)   # 128
print(cfg.batch_size)   # 512
~~~

`@dataclass` 根据字段自动生成初始化、打印表示等常见方法，使配置集中管理。类型注解用于说明预期类型和帮助静态检查，**不会自动实施运行时类型校验**；需要严格校验时要另写逻辑。它也不只允许“纯数据容器”，可以配合自定义方法或 `__post_init__`；本项目用它存配置最直接。

`hidden_dim` 决定隐藏层宽度，影响模型容量和计算量；`batch_size` 决定一次处理多少个样本，影响梯度估计、内存和更新次数。增加 batch 大小不会自动增加网络的神经元。

类描述一类对象的属性和行为；调用类创建实例时，Python 会执行其初始化流程，其中 `__init__` 为实例设置属性、准备数据。`self` 是当前实例的引用。需要被其他方法继续使用的数据保存在 `self.features` 等属性中；只在生成数据时使用的 `num_frames`、`seed` 可以保留为局部参数。

### 从通信样本到分类样本

每个模拟块有 48 个数据子载波，每个子载波形成一条样本：

| 内容 | 形状或类型 | 含义 |
|---|---|---|
| `features` | `[num_frames * 48, 4]`，`float32` | `[Re(y), Im(y), Re(h_ls), Im(h_ls)]` |
| `labels` | `[num_frames * 48]`，`int64` | QPSK 的四分类编号 |
| 单条样本 | 特征向量和一个标签 | 不包括真实信道作为网络输入 |

`np.empty(...)` 预分配存储空间，其内容尚未初始化，必须在读取前全部填好。`features[start:stop]` 每次填入一个块的 48 行：第 0 块为 `[0:48]`，第 1 块为 `[48:96]`，切片右端不包含。

分类标签的对应关系用一小段数据就能检查：

~~~python
import numpy as np

bits = np.array([0, 0, 0, 1, 1, 0, 1, 1], dtype=np.int8)
pairs = bits.reshape(-1, 2)
labels = 2 * pairs[:, 0] + pairs[:, 1]
print(labels)  # [0 1 2 3]
~~~

`reshape(-1, 2)` 按两列整理，行数自动推算。分类编号与第一周星座映射保持一致。

`torch.from_numpy()` 将数组包装成张量，在支持的 CPU 数组上共享底层存储；它不是“必然复制一份”。本项目生成完后不再修改原数组，接口较清楚。

`Dataset` 接口中，`__len__` 对应 `len(dataset)`，`__getitem__` 对应 `dataset[index]`。双下划线方法用于实现 Python 或框架约定的协议；普通加法函数直接写 `def add(x, y)` 即可，只有要为自定义对象定义 `+` 的行为时，才考虑 `__add__`。

`simulation_signature()` 保存通信参数、特征次序和 QPSK 星座映射。`np.column_stack(...).tolist()` 把复星座拆成实部、虚部两列，再转成普通列表，便于保存和比较。函数中的 `return` 返回对象给调用者，只有 `print(...)` 才会主动在终端显示。

## 5. 实验或问题分析

4000 个模拟块对应 192000 条训练样本，600 个块对应 28800 条验证样本。它们是按配置推算的规模，**不是当天已经训练完成的实验记录**。

一个块的 48 条样本共享同一组信道抽头，存在相关性。正常训练应按完整块分别生成训练和验证数据，避免先拼接数据再把同一块的子载波随机拆到两边。之后的三种模式、训练结果和安装问题统一记在 [11 月 8 日日志](05_2026-11-08_调试与评估.md)。

原对话曾把每块重新生成的信道称为“时变信道”；当前实现只是在块与块之间重新抽样，单个 OFDM 符号内保持不变，还没有实现多普勒引起的符号内变化。
